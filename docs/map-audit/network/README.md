## 길이와 높이 재계산

`node tools/survey_streets.mjs`로 아래 표를 다시 생성한다. 범위는 저장소에 들어 있는 지도 추출본 전체다. 서울 고속터미널 외에 인접 역과 한강까지 포함한다. 이 중 네이버 화면에서 직접 대조한 범위는 위 표와 같다.

- [도로·보행로 1,274건](ways.csv)에는 서로 다른 OSM way 1,255개의 구간별 좌표, 도로 분류, 구조물, 소유 모듈, 굴곡을 따른 평면 길이와 WGS84 타원체 근사 길이를 담았다. 370개 footway, 25개 path, 22개 steps, 8개 pedestrian이 포함된다. 같은 원본 좌표에서 두 계산법의 차이는 가장 긴 차이가 5.56m였다. 두 값은 현장 줄자 측정값이 아니다. `claim_or_default`는 모듈 배정이며 렌더 여부나 보행 성공을 뜻하지 않는다.
- [지도 기준점 197개](controls.csv)에는 신호 노드 39개, 횡단 노드 130개, 지하철 출입구 노드 28개의 경위도와 지표 표고를 담았다. 신호 노드는 교차로의 지도 표식이며 신호기 기둥의 실측 좌표와 설치 대수는 별도 확인 대상이다.
- [모듈 연결 19건](junctions.csv)은 통로 16개 층·연결 조합과 인접 모델 표시용 연결 3건으로 구분했다. 길이는 등록된 양 끝점 사이 직선거리이다. 계단·곡선 복도를 따라 걷는 거리에는 사용할 수 없다.

프로젝트 원점은 북위 37.5050371°, 동경 127.0049222°다. 월드 x는 동쪽, z는 남쪽이며 원본 변환 계수를 역산해 경위도를 복원했다. 표고는 서울 등고선·표고점 기반 25m 간격 지형에서 삼각형 보간 후 원점 기준값 11.838m를 더했다. 기준점 표에는 모델에서 별도로 보정한 지표와의 차이도 있다. 지하도·고가도·육교의 도로 양 끝에 적힌 값은 해당 좌표 **지표**의 높이다. 플랫폼·교량 상판·실내층고는 지형값으로 맞추지 않았다. 원자료의 수직 기준면은 명시되지 않았다. [서울시 등고선·표고점 자료](https://data.seoul.go.kr/dataList/OA-22241/F/1/datasetView.do)


[터미널 주변 등고선·도로·신호·출입구 지도](contours.png)에는 25m 삼각 지형에서 보간한 2m 등고선을 표시했다. 좌표축은 WGS84, 축척막대는 프로젝트 평면 거리다. `uv run tools/plot_terminal_survey.py`로 다시 그릴 수 있다.

## 신호기와 옥상 전광판

2026년 1월 고속터미널사거리 거리뷰에서 가로 차량 신호대와 G14 방면 교통섬의 적색 보행 신호·점자블록을 확인했다. 모델에서는 OSM이 무신호로 표시한 횡단부 두 곳에 보행 신호기를 생성하던 문제를 수정했다. 기준점 CSV의 `crossing_control`에서 원본 태그를 볼 수 있다. 기둥 위치와 신호 주기는 실측하지 않았다. [교차로 서향](https://map.naver.com/p?c=18.00,0,0,0,adh&p=mU8aHacBJYgq0X7dtSPrtw,-88,10,80,Float) · [교통섬 보행 신호](https://map.naver.com/p?c=18.00,0,0,0,adh&p=mU8aHacBJYgq0X7dtSPrtw,-58,0,40,Float)

르본시티 옥상 전광판은 비활성화된 옛 거리 모듈에 남아 있었다. 건물 모델에 복구하고 2026년 1월 거리뷰의 흰 화면·붉은 머리글·어두운 본문 배열을 반영했다. 화면 문구와 판의 치수는 판독할 수 없었다. [르본시티 네이버 거리뷰](https://map.naver.com/p?c=18,0,0,0,adh&p=FmNf2XmJtk1RjDP3k0TI7A,230,18,51,Float)
