## 편집과 배치

`hokyung.blend`의 `SSG_11F_Hokyung_Dining` 컬렉션에는 편집 가능한 메시 오브젝트 302개와 내장 표면 아틀라스 하나가 있다. 단위는 미터다. 손님상 중심 아래 바닥이 원점이고 Blender +Z는 위, +Y는 솥이 놓인 쪽이다. glTF Y-up 변환 뒤 월드 +Y축으로 20.780751° 회전한다. 층 기준 원점은 (−51.292023, 50.2, 68.274779), 지형 적용 후 월드 원점은 (−51.292023, 49.292, 68.274779)이다. 다음 요리를 놓을 옆 식탁의 상판 중심은 Blender 로컬 (−2.1, 0, 0.765)이다.

## 빌드와 확인

저장소 루트에서 Blender 3.6.23과 설치된 Node 패키지로 확인했다. 별도 시스템 글꼴은 쓰지 않는다.

```sh
D=assets/models/ssg-hokyung-dining
"${GTW_BLENDER_BIN:-blender}" -b --gpu-backend opengl --factory-startup --python-exit-code 1 -P "$D/build.py"
node "$D/pack.mjs"
node tests/smoke.mjs shinsegae
node tests/smoke.mjs shinsegae gotomall
```

원본을 직접 편집한 경우 첫 Blender 명령을 다음 명령으로 바꾼다.

```sh
"${GTW_BLENDER_BIN:-blender}" -b --gpu-backend opengl "$D/hokyung.blend" --python-exit-code 1 -P "$D/export.py"
```

배포 GLB는 564,472바이트, 삼각형 48,030개, 메시·재질 각 5개로 근접 표시 시 5회 그린다. 누룽지 속에 완전히 묻힌 낱알 면을 배포본에서 덜어 삼각형 9,048개를 줄였다. 저장한 Blender 원본에서 다시 내보낸 GLB의 SHA-256은 처음 만든 파일과 일치했다. 단독 및 고투몰 연동 스모크 테스트가 모두 통과했다. 일반 게임에서 7층과 같은 층 원거리에서는 호경전 GLB 요청이 없었고, 손님상 앞에서는 한 번 요청했다. 두 촬영 시점 모두 HUD에 ‘호경전 (모던 차이니즈 푸드) · 11F’가 표시됐다.

## 가지덮밥을 올린 두 번째 식탁

이 식탁에는 강남점 손님이 2024년 11월에 주문하고 여러 각도에서 촬영한 가지덮밥을 차렸다. 밥보다 많은 가지볶음, 다진 돼지고기와 청·홍고추, 흰 접시에 담긴 밥, 맑은 국과 파, 단무지와 짜사이가 사진에 나온다. 배식 양과 식기 치수는 사진 비례로 추정했다. 검은 젓가락과 국 숟가락까지 게임의 두 번째 호두나무 식탁에 맞췄다. 가지는 열두 조각으로 잘라 자주색 껍질, 익은 속살, 소스가 달라붙은 면을 각각 표현했다. 밥 둘레의 소스가 곡면을 이루고, 잘게 썬 고추와 다진 재료가 그 위에 얹혀 있다. 손님상에 쓰인 편집 메시 198개를 더해 전체 컬렉션은 500개다. Blender 좌표 (−1.83, −0.23, 0.765)m에서 90° 회전해 올렸다.

상세 음식은 340,384바이트, 삼각형 17,465개, 드로 1회다. 조리 내용물을 작은 접시에 맞춰 독립적으로 불러온다. 3.5m 안에서 보았을 때 1회, 같은 층 6m 거리와 다른 층, 천장을 본 경우는 0회였다. 왕복 보행에서도 총 요청은 1회였다. 9m 이내에서 간단한 접시가 보인다. 저장한 원본에 `meal_export.py`를 실행한 뒤 `node meal_pack.mjs`로 압축했을 때 같은 GLB가 나왔다. 기존 홀과 누룽지탕 GLB도 동일하다.
